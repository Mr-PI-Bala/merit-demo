## Current release decision

The consumer is **not yet ready for subscriber alpha**. Registration is reachable and the V01 provider gateway is healthy, but an alpha session cannot be issued because onboarding returns HTTP 500. The canonical default provider also needs the v0.1.99 gateway deployment promoted; it currently returns HTTP 404 for the gateway health route.

### Required recovery order

1. **Provider owner:** promote the v0.1.99 gateway to the canonical `merit-prod.vercel.app` deployment and repeat gateway health.
2. **MeritSubs/provider owner:** repair the upstream onboarding function and its Supabase/runtime configuration; prove a disposable subscriber is created with `consumer_id=merit-demo-alpha`.
3. **Consumer owner:** run the default checks again, then run the full browser journey from registration to member session.
4. **Release gate:** only call the consumer alpha-ready after canonical health, registration, onboarding, token issuance, tenant isolation, and the documented user journeys all pass.

## Reproduction commands

From `C:\DApps\merit-demo`:

```powershell
npm run verify
npm run test:alpha-registration
npm run test:alpha-session
$env:MERIT_PROD_BASE_URL = 'https://merit-prodv01.vercel.app'
npm run test:alpha-session
Remove-Item Env:MERIT_PROD_BASE_URL
node scripts/serve.mjs
```

The default session check intentionally uses canonical production. The environment override is for provider-owner testing only; it does not change the checked-in consumer contract.

## TDD and evidence gate

The checks are red-first: a missing route, wrong redirect, wrong consumer header, failed onboarding, or mismatched tenant must fail the command. A green release requires both automated output and a screenshot of the corresponding browser pathway. The next provider fix must add a passing onboarding assertion before any alpha readiness claim is changed.
